- **Call Audio Noise / Not Stopping**: Reported background noise during calls that kept playing after the call ended. Three causes fixed. (1) `ontrack` was attaching the remote `MediaStream` to *both* `remoteVideo` and `remoteAudio` — the doubled audio phase-flips into noise. The remote stream now goes to exactly one element: `remoteVideo` for video calls, `remoteAudio` for audio-only calls. The audio-only stream is no longer attached to `remoteVideo` at all, because that `<video>` carries `autoplay` and would fight the `pause()`. (2) `endCall()` awaited the Firestore `update` *before* `cleanupCall()`, so if that write hung the call audio never stopped — cleanup now runs first and the Firestore write is fire-and-forget. `cleanupCall()` also stops the remote tracks (`callRemoteStream`), not just the local ones. (3) Audio constraints were `audio: true`; now explicitly `echoCancellation`, `noiseSuppression` and `autoGainControl` are all on via `CALL_AUDIO_CONSTRAINTS`/`getCallStream()` in both `startCall()` and `acceptCall()`.
- **Switch Camera (video calls)**: Video calls were stuck on the front camera. New "Flip" button in the active-call controls (`#flipBtn` in `UserChat.jsx`, bound to `switchCamera()` in core). `switchCamera()` opens the other camera with `getUserMedia({ facingMode })` and swaps it in with `RTCRtpSender.replaceTrack()`, so the call does not renegotiate or drop. The old track is removed from `callLocalStream` and stopped, the local preview is re-attached, `newTrack.enabled` follows `isVideoOn` so switching while muted-video keeps it off, and `callFacingMode` is tracked from `getSettings().facingMode` and reset on every new call. Rapid double-taps are blocked by a `switchingCamera` guard; failure (single-camera devices) alerts and stops the throwaway track. `showActiveCallUI()` dims the button on audio calls, and `.call-bottom-controls` gained `flex-wrap: wrap` so the fifth control does not push End off small screens.
- **Call Lifecycle / Real-time Fixes**: Five bugs behind "cancel par bhi call screen rehti hai", "accept karne par kuch nahi hota" and "call beech me kat jaati hai".
  1. `listenForIncomingCalls()` only handled `status === 'ringing'` and never reacted to a *status change*. When the caller cancelled, the callee's ring screen + ringtone stayed up for the full 30s `missedTimeout`. It now watches its own `currentCallData.callId` and calls `cleanupCall()` the moment status becomes `ended`/`declined`/`missed`. Same pass also auto-declines a new incoming call when the user is already busy on another one (previously the `!currentCallData` guard meant it just rang out).
  2. ICE candidates were applied with a bare `try/catch` *before* `setRemoteDescription` resolved, and the counter was incremented regardless — a candidate that failed was lost forever, so the call looked connected but no media flowed. Candidates now go through `addIceSafe()` into `pendingIceCandidates` when there is no remote description yet, and `flushPendingIce()` drains them after it is set (in `acceptCall()` and in the new awaited `applyAnswer()`).
  3. The caller's `setRemoteDescription(answer)` was a floating un-awaited promise, so ICE could be processed out of order. Replaced with async `applyAnswer()`, guarded by `applyingAnswer`, which also clears `missedTimeout` once answered.
  4. `onconnectionstatechange` killed the call instantly on `disconnected` (a normal transient mobile state) and only called `cleanupCall()` — never wrote `status: 'ended'`, so the other side hung on a dead call. Now `connected` cancels a pending fail timer, `failed`/`closed` call `endCall()` (which writes the status), and `disconnected` gets an 8s grace period first.
  5. Handlers were attached to the global `callPeerConn`, so a stale connection's `ontrack`/`onicecandidate` could target a newer call's doc and DOM. `setupPeerConn()` now captures `const pc = callPeerConn` and every handler bails if `callPeerConn !== pc`; `cleanupCall()` nulls `callPeerConn` *before* `pc.close()` to avoid re-entry. State (`pendingIceCandidates`, `applyingAnswer`, `connFailTimer`) is reset in `startCall()`, `showIncomingCall()` and `cleanupCall()`.
  Also: `listenForIncomingCalls()` is re-subscribed on `visibilitychange` alongside `listenUsers()`, because mobile browsers throttle snapshot listeners in the background and calls were being missed.

- **Lag Fix Level 1 (A–D)**: Four changes behind "kabhi kabhi lag karta hai / hang hota hai". None of them touched design.
  1. **`renderUsers()` diff guard** (`script-core.js`): the 15s heartbeat writes `users/{myId}` *and* every online user's heartbeat does the same, and `listenUsers()` watches the whole collection — so `renderUsers()` ran constantly and did `list.innerHTML = …` every time, deleting and re-creating every avatar `<img>` (re-decode) for data that had not changed. It now builds a `renderSig` of exactly the fields that are rendered (id, active row, online flag, name, photo, status text incl. the time-bucketed "Last seen …") and returns early when it is unchanged. `onlineCount` still updates every time.
  2. **Voice/video conversation polls** (`script-voice.js`, `script-video.js`): `setInterval(loadVoiceConvMsgs, 3000)` rebuilt `#voiceConvMsgs`' whole `innerHTML` every 3 seconds (same for video). Now each side computes `JSON.stringify(data) + '|' + Math.floor(Date.now()/60000)` — the minute bucket keeps the relative "2m ago" timestamps fresh — and skips the DOM write when it matches. `voiceConvRenderSig`/`videoConvRenderSig` are reset in `openVoiceConv`/`closeVoiceConv` so a different conversation always repaints.
  3. **Cache busting** (`vite.config.js`, `UserChat.jsx`, `script-core.js`): `loadScript('/script-core.js?v=' + Date.now())` gave the 99 KB script a *new* URL on every single page load, so it was never cached. It now uses `__BUILD_ID__` (`String(Date.now())` in `vite.config.js`'s `define`, evaluated once per build) — cache is dropped only on a new deploy. `ensureScriptLoaded()` gained the same `?v=` (it had **no** version at all, meaning `script-voice.js`/`script-video.js` could never refresh); the id reaches `public/` code via `window.__BUILD_ID__`, since those files are not in the bundle.
  4. **Global typing/recording listeners** (`script-core.js`): `listenGlobalTyping()`/`listenGlobalRecording()` subscribed to the *entire* `typing`/`recording` collections with no unsubscribe variable (they re-stacked on re-login) and iterated **all** docs with `snap.forEach()` on every keystroke. Both now keep `unsubGlobalTyping`/`unsubGlobalRecording`, call them before re-subscribing, iterate only `snap.docChanges()`, skip `removed`, and are cleared in `logout()` together with `unsubNewMsgNotif`/`unsubBroadcast`.
- **Custom Chat Keyboard (device keyboard disabled)**: Tapping the message box no longer opens the phone's soft keyboard — `#messageInput` carries `inputMode="none"` (+ `autocomplete`/`autocorrect`/`autocapitalize`/`spellCheck` off) and a new `src/pages/user/ChatKeyboard.jsx` slides in a full QWERTY keyboard of its own. Rendered at the root of `UserChat.jsx`, **not** inside `.page`, because `.pages-container .page` has `will-change: transform`, which would capture `position: fixed`. Behaviour: opens on `focus`/`click` of `#messageInput` with a 0.3s slide (`.chat-kb` → `translateY(0)`), and minimises on **any tap outside the keyboard** (document `pointerup` capture; a >12px move is treated as a scroll so scrolling the conversation does not dismiss it) — tapping the input itself keeps it open so the caret can be repositioned. `.main-app.kb-open` sets `padding-bottom: var(--kb-h)` (measured by a `ResizeObserver`) and hides `.bottom-nav`, so the input bar always sits directly above the keyboard. Features: QWERTY letters, Shift (tap = one-shot, double-tap = caps lock, auto-capitalisation at start of message and after `.!?`), a Gboard-style third row whose left key is `⇧` / `=\<` / `123` per mode, a numbers page and a symbols page (`?123` / `ABC` in the bottom row), backspace with 400ms long-press repeat, comma/period/space, a 48-emoji panel (`.kb-emoji-panel`, always mounted and `max-height`-transitioned so the keyboard and the chat area grow in step) and a Send key that calls `sendMessage()`. Every insert writes `el.value` + `setSelectionRange` and then dispatches a real `input` event, so the pre-existing `autoResize`/`handleTyping` handlers keep working; keys `preventDefault()` on `pointerdown` so focus never leaves the textarea. Safety net: if a device ignores `inputMode="none"`, a `visualViewport` resize listener detects the 120px+ shrink (with `scale` guards against pinch-zoom) and sets `readonly` on the box — which does not block programmatic typing.
- **App Keyboard is now opt-in (device keyboard is the default)**: the custom keyboard no longer takes over on its own. `#messageInput` carries **no** `inputMode`/`autocomplete`/`autocorrect`/`autocapitalize`/`spellCheck` attributes, so out of the box the user gets their device keyboard with all its normal autocorrect and auto-capitalisation. The setting lives in `helpers.js` (`isAppKeyboardEnabled()` / `setAppKeyboardEnabled()` / `onAppKeyboardChange()`, backed by `localStorage['chatAppKeyboard']` with a module-level fallback for private mode, broadcast on a `appKeyboardChanged` window event so no React prop drilling is needed) and its switch is a new **"Keyboard → App Keyboard"** section on the Profile page (`#kbToggleRow`/`#kbToggleDesc`/`#kbToggle`/`#kbToggleInput`), reusing the existing `profile-section` + `push-toggle-row` + `ios-toggle` classes so no CSS was added. `ChatKeyboard.jsx` keeps the input attributes in one `applyKeyboardAttrs()` — set when the flag is on, **removed** when it is off — refuses to open on `focus`/`click` when off, skips the `visualViewport` safety net when off, and closes itself immediately if the user flips the switch while it is open. `defaultChecked={isAppKeyboardEnabled()}` seeds the toggle on mount.

## Key Decisions
- Used `sql.js` (pure JS SQLite) instead of `better-sqlite3` because Windows lacks Visual Studio build tools
- Used `prepare()`/`step()`/`getAsObject()` in voices.js instead of `database.exec()` for reliable data retrieval
- Voice page uses bottom-sheet pattern (not full page) for recording/preview states
- Recording indicator uses Firestore `recording/{convId}` collection with `onSnapshot` listener
- `setRecordingStatus(true/false)` called on start/stop/cancel of voice recording
- Pagination attempt (`limitToLast` + `onSnapshot`) removed — causes Firestore listener issues with new messages
- "NEW" badge changed from time-based (24h) to play-status-based (localStorage `listenedVoices` array)
- File split approach: SPA with CSS/JS split (not 3 separate HTML pages)

## Critical Context
- `listenMessages()` uses simple `orderBy('created_at', 'asc')` with no limit — all messages load but chat works reliably
- `loadedMsgIds` Set prevents duplicate rendering
- Voice recordings NEW badge uses `localStorage` key `listenedVoices` (array of recording IDs)
- Mobile layout fixes applied globally
- HTTP API base: `VOICE_API` variable points to backend
